What an agent is

A chat answers.
An agent acts.

readsplansedits
runschecks

It opens your files, writes a plan, edits code and runs commands in your terminal. Then it reads what comes back.

The last step is the one that matters. An agent that runs your app and looks at the result can fix its own mistakes. One that can’t is guessing.

You stay the designer. You set the goal, approve the plan and judge the result.

ai/strategy.md

Memory you can read.

# Strategy
## Goal
A page where you paste text and see live
word, character and sentence counts.
## Plan
- [x] Tests for the stats functions
- [x] src/stats.js until the tests pass
- [x] index.html: a text box, four numbers
- [ ] Style it
## Decisions
- 2026-10-23 Count characters as graphemes
  because "é" and emoji should count as 1
## Next
- Style it: calm, large numbers

The goal in one sentence. The plan as checkboxes. One line per decision, always with because. The next step.

Every session starts by reading it, so a fresh agent knows where you are. So do you, tomorrow morning.

No context section, no essays. If it gets long, the steps are too big.

Ignore rules

What the agent must never read.

Secrets

.env*

A key in a prompt is a leaked key.

Dependencies

node_modules/

Thousands of files nobody here wrote.

Binaries

public/splats/*

Megabytes of numbers. No meaning for a language model.

Cost

every file read

is paid input, and is sent again on every step.

.gitignoreGit never stores it.
.ignoreAgent search skips it.
deny rulesThe tool refuses to open it.

Ignore hides. Deny locks. Neither is a vault: keep secrets out of project folders altogether.

Introspective mode

The agent looks at its own screenshot.

$ npm test
ℹ tests 7
ℹ pass 7
ℹ fail 0

$ npm run check
check: OK (0.4 s)
  ready after 0.2 s, 0 errors, 0 warnings,
  4/4 app checks
  screenshot: background #f1efea, 21% of
  pixels differ from it
  see .check/report.json and
  .check/screenshot.png

npm test checks the logic. npm run check opens the real page in a hidden browser, waits until the app says it is ready, and writes a report and a screenshot.

The agent reads both, fixes what it finds and runs the check again.

The report also describes the screenshot in words and numbers, for models that can’t see images.

Exercise · Text stats

Prompt 1: plan

Read AGENTS.md and ai/strategy.md. We are building a small web page: a text box where I paste text, and below it live counts of words, characters and sentences, plus the reading time. Put the counting logic in src/stats.js as pure functions and export textStats(text), which returns { words, characters, sentences, readingMinutes }. Test it with node:test in tests/stats.test.js. Fill in the Goal and a plan of 4 to 6 small steps in ai/strategy.md. Don't write code yet.

Start the agent in your project folder. Keep a second terminal for your own commands.

Read the plan in ai/strategy.md. Change it if you disagree.

The plan is yours.

Exercise · Text stats

Prompt 2: build, tests first

First

Go with step 1. Write the tests in tests/stats.test.js first, run npm test and show me that they fail. Then write src/stats.js until they pass. npm run check will still say "Nothing rendered yet": that is fine until the page exists. Tick off the step in ai/strategy.md and stop.

Then

Continue with the next steps: index.html and src/main.js, so the page shows the four numbers live while I type. Mark each number with data-stat="<key>", using the keys from textStats(). Then simple styling: calm, readable, large numbers. Set window.__APP_READY__ = true when the page is ready. One step at a time. After each step run npm test and npm run check, tick it off in ai/strategy.md and tell me what you see in the screenshot.

Prompting

Good habits.

Ask for a plan first.

“Don’t write code yet” is a feature, not a delay.

One small step at a time.

Big steps fail in big, confusing ways.

Say what “done” means.

“The check passes and the screenshot shows four numbers.”

Name the files.

“In src/stats.js” beats “somewhere in the code”.

Paste facts, not feelings.

The summary from the report, not “it’s broken”.

New task, new session.

Long sessions get slow, expensive and confused.
